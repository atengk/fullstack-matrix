# 空间地理信息系统 WebGIS 与遥感空间数据服务 (Spatial GIS & Remote Sensing)

## 1. 模式 A：企业级空间地理数据底座与 OGC 地图瓦片服务 (PostgreSQL/PostGIS + GeoServer + QGIS)

### 1.1 核心技术栈清单与职责说明
| 架构层级 | 推荐选型 | 职责与功能定位说明 |
| :--- | :--- | :--- |
| **空间地理关系型数据库底座** | `PostgreSQL 16+` + `PostGIS 3.4+` | 地理空间计算事实标准，提供 1000+ 专业空间算子、R-Tree (GiST/SP-GiST) 空间几何索引与高维拓扑分析能力 |
| **企业级 OGC 地图服务发布引擎**| `GeoServer 2.25+` / `MapServer` | 工业级开源地图服务器，严格遵循国际 OGC 标准规范，发布 WMS (栅格)、WFS (要素)、WMTS (切片) 与矢量瓦片服务 |
| **桌面级专业空间制图与拓扑清洗**| `QGIS 3.x` | 顶级开源桌面地理信息系统，负责空间图层清洗拓扑校验、坐标系投影纠偏、空间符号化渲染与 SLD 样式配置导出 |
| **动态矢量瓦片极速直出中间件** | `pg_tileserv` (轻量 Go 服务) / `tippecanoe` | 零配置直连 PostGIS 数据库，毫秒级将百万空间多边形切片输出为标准 Mapbox 矢量瓦片（MVT），消除静态切片存储开销 |
| **万能空间坐标系统与投影纠偏** | `GDAL/OGR` + `PROJ 9.x` | 底层空间数据抽象转换库，精准纳管 CGCS2000 (国家 2000 大地坐标系)、WGS84、GCJ02 (火星坐标) 与 BD09 间的互转纠偏 |

### 1.2 核心选型考量与技术优势
* **PostGIS 空间算力统治力（消除应用层低效计算）**：
  * 传统数据库只能保存经纬度数值，当查询“该车辆是否在电子围栏多边形内”或“方圆 5 公里内所有巡检人员”时，应用层需拉取海量数据暴力计算；
  * PostGIS 内置专业空间索引与几何算法，一条 SQL（如 `ST_DWithin`、`ST_Contains`）即可在千万级复杂多边形与点线要素中以毫秒级返回空间拓扑运算结果；
* **OGC 国际工业级标准输出与国产信创无缝替代**：
  * GeoServer 遵循 OGC 标准输出接口，前端无需绑定任何特定地图厂商，一套切片服务可无缝供 Web、APP、桌面专业 GIS 软件同步消费；
  * 底座 PostgreSQL + PostGIS 完美兼容国产人大金仓（KingbaseES）、达梦（DM8）、华为高斯（openGauss）等信创数据库，彻底摆脱国外 Esri ArcGIS 昂贵商业软件的垄断与制裁风险；
* **矢量瓦片 (MVT) 革命性降本提速**：
  * 摒弃旧时代预先在服务器硬盘上预切成千上万张静态 PNG 图片（占用数 TB 磁盘且数据一变更就得重新切图数天）的落后方案；
  * 采用 `pg_tileserv` 实时查询 PostGIS 并以 Protocol Buffers 二进制流格式下发矢量瓦片，数据更新秒级在线可见，传输体积缩小 80% 以上，支持前端自由动态换色。

### 1.3 适用业务场景
* 国土资源规划一张图、林业与水利防汛数字孪生空间底盘、城市地下三维综合管网拓扑；
* 物流车队全局调度监控、海量轨迹回放、电子围栏跨界报警与冷链配送区域智能划分；
* 应急救援指挥中枢、气象雷达降雨反演图层与政务地理信息跨部门共享交换平台。

## 2. 模式 B：现代化 Web 端 2D/3D 地理空间可视化引擎 (CesiumJS + OpenLayers / MapLibre GL)

### 2.1 核心技术栈清单与职责说明
| 架构层级 | 推荐选型 | 职责与功能定位说明 |
| :--- | :--- | :--- |
| **三维数字地球与实景渲染引擎** | `CesiumJS 1.120+` (基于 WebGL/WebGPU) | 现代化三维空间地理领航引擎，精准模拟地球椭球体曲率、大气光照、全球地形高程起伏与星空太阳星历 |
| **倾斜摄影与白模流式资产标准** | `3D Tiles 1.1` (OGC 官方三维流式规范) | 分层细节（LOD）流式三维切片规范，支持按视距动态按需下发数千平方公里无人机倾斜摄影与百万建筑物白模 |
| **专业高精度二维交互与测绘引擎**| `OpenLayers 10.x` | 测绘级纯前端 2D 地图引擎，支持任意自定义地理坐标系（投影即变换）、专业标绘、几何量算与海量矢量图层编辑 |
| **轻量极速矢量地图渲染底座** | `MapLibre GL JS 4.x` (WebGL/WebGPU) | 纯开源现代化矢量地图渲染库，支持 60fps 丝滑旋转倾斜、动态矢量瓦片样式切换、3D 建筑挤压与热力图 |
| **前端纯算空间几何拓扑工具** | `Turf.js` (先进的纯 JavaScript 空间分析库) | 在浏览器本地快速执行两点测距、多边形测面、点线缓冲区（Buffer）生成、凸包计算与交集布尔运算，零远程 RPC 延迟 |

### 2.2 核心选型考量与技术优势
* **宏观数字地球与实景无人机航拍完美融合 (CesiumJS)**：
  * 与第 11 节的 Three.js 侧重于厂房内部小微设备精细拆解不同，CesiumJS 专职解决城市与全球尺度的宏观三维渲染；
  * 依托 `3D Tiles` 树状空间索引，即便加载几十吉字节的无人机激光点云与全区倾斜摄影模型，浏览器内存也绝不爆炸，远近视距自动平滑渐变切换细节，呈现真实震撼的数字地球；
* **完全自主可控（终结高德/百度公网 API 商业闭源税）**：
  * 传统政企项目采用商用互联网地图 API，不仅面临局域网内无法联网、坐标偏移加偏、私有数据回传云端的严重安全隐患，且面临高昂的商用授权年费；
  * MapLibre GL 与 OpenLayers 100% 部署在私有内网服务器，瓦片底图完全自主托管，支持军工政务严格保密内网环境 24/7 独立离线运转；
* **毫秒级前端本地几何运算 (Turf.js)**：
  * 在大屏或移动端执行电子围栏绘制、测距量面或路径轨迹拟合时，无需向后端发起网络请求等待数据库返回，前端通过 Turf.js 直接在内存中毫秒级输出拓扑分析结果，交互体验丝滑无阻。

### 2.3 适用业务场景
* 智慧城市三维实景底盘、无人机全自主航线规划与三维电子沙盘推演指挥；
* 园区数字孪生宏观鸟瞰、建筑信息模型（BIM）与地理信息（GIS）跨尺度融合（BIM+GIS）；
* 交通物流监控大屏、港口码头自动化泊位导航、外网物理隔离的保密内网地图中枢。

## 3. 双模式选型决策对比与建议

| 评估维度 | 模式 A：空间地理数据底盘与地图服务 (PostGIS + GeoServer) | 模式 B：Web 前端 2D/3D 空间可视化 (CesiumJS + OpenLayers) |
| :--- | :--- | :--- |
| **系统架构层级** | 空间数据存储、几何算子计算、标准 OGC 协议服务发布端 | 浏览器端图形渲染、地图交互、用户标绘量算与大屏呈现端 |
| **主导核心栈** | `PostgreSQL 16` + `PostGIS 3.4` + `GeoServer` + `QGIS` | `CesiumJS 1.120+` + `3D Tiles` + `OpenLayers` + `Turf.js` |
| **核心处理对象** | 千万级空间多边形、点线图层属性表、拓扑关系、空间索引 | 3D 网格模型、地形高度图、倾斜摄影切片、矢量瓦片着色 |
| **坐标计算精度** | 严谨大地测绘级精度（支持毫米级椭球体投影转换与几何拓扑） | 像素级图形投影与视椎体剔除，依托 GPU 着色器硬件加速渲染 |
| **对外服务契约** | 标准化 OGC WMS、WFS、WMTS、MVT 协议二进制网络服务 | WebGL/WebGPU 画布、Canvas 交互图层、DOM 悬浮标绘弹窗 |
| **两者协同关系** | 充当 WebGIS 的“空间大脑与数据仓库”（后端算子与瓦片发布） | 充当 WebGIS 的“交互眼睛与可视化视口”（接收瓦片渲染呈现） |
